# 代码修复飞书集成参考

本文件定义 `cc-code-fixer` 使用 `lark-cli` 读取审查结果、更新修复状态和降级回退的规则。所有飞书操作均通过 `lark-cli` 完成，禁止使用旧版 `feishu_create_doc` 或 `feishu_bitable_*` 工具。

---

## 一、通用规则

- 飞书操作失败不得阻塞本地修复报告生成。
- 写操作前必须先读，确认目标文档或表格存在。
- 多维表格更新必须按问题编号或记录 ID 精确定位，不允许批量覆盖整表。
- 修复状态、修复时间、修复分支必须与本地报告保持一致。
- 如果飞书不可用，进入 degraded mode，并在本地报告「飞书同步结果」中记录失败原因。

---

## 二、读取飞书云文档

适用输入：`https://.../docx/...` 或 `https://.../docs/...`

### 2.1 读取命令

```bash
lark-cli docs +fetch --url "{DOC_URL}" --format markdown
```

如果 CLI 只返回文档 token，应先提取 token，再使用对应读取命令。读取结果必须保存为临时 Markdown，用于后续问题解析和最终审计。

### 2.2 读取失败处理

读取失败时：

1. 不执行代码修复。
2. 输出失败命令和错误摘要。
3. 提示用户改用本地 Markdown 报告或飞书多维表格。
4. 如果已经有可用的本地缓存，只能在用户确认后继续。

---

## 三、读取飞书多维表格

适用输入：Base URL 或 `base:{BASE_TOKEN}:{TABLE_ID}`。

### 3.1 表结构要求

至少需要以下字段：

| 字段 | 用途 |
|------|------|
| 问题编号 | 匹配修复项 |
| 严重级别 | 确定默认修复顺序 |
| 问题描述 | 理解问题 |
| 位置 | 定位代码 |
| 修复建议 | 生成修复计划 |
| 修复状态 | 过滤待修复记录并写回结果 |
| 修复时间 | 写回完成时间 |
| 修复分支 | 写回修复所在分支 |

### 3.2 读取命令

```bash
lark-cli base +record-list --base-token "{BASE_TOKEN}" --table-id "{TABLE_ID}"
```

如果命令环境要求显式子命令前缀，可使用等价的 `lark-cli base` 读记录命令，但必须保持同一 CLI 家族，不混用旧工具。

### 3.3 记录过滤

默认只修复：

- `修复状态` 为空
- `修复状态` 为 `待修复`
- `修复状态` 为 `修复中` 且用户明确要求继续

不默认处理 `已修复`、`已忽略`、`不适用` 的记录。

---

## 四、更新飞书多维表格

### 4.1 状态映射

| 本地修复状态 | 写回 `修复状态` |
|--------------|----------------|
| 已修复 | 已修复 |
| 部分修复 | 修复中 |
| 未修复 | 待修复 |
| 已忽略 | 已忽略 |
| 待人工确认 | 待修复 |

### 4.2 写回字段

每条参与修复的问题必须写回：

- `修复状态`
- `修复时间`
- `修复分支`
- `备注`

`备注` 中写入本地报告路径、验证命令摘要和未完成原因。不要把完整 Markdown 报告塞入单元格。

### 4.3 更新命令

```bash
lark-cli base +record-update \
  --base-token "{BASE_TOKEN}" \
  --table-id "{TABLE_ID}" \
  --record-id "{RECORD_ID}" \
  --json '{"fields":{"修复状态":"已修复","修复时间":"2026-05-07","修复分支":"codex/fix-auth","备注":"本地报告: code-fix-report-demo-20260507-153000.md；验证: mvn test 通过"}}'
```

更新前必须确认 `RECORD_ID` 来自读取结果。无法匹配记录时，只在本地报告中记录，不创建新记录。

## 五、更新或创建飞书云文档

如果用户要求输出到云文档：

1. 优先创建新的修复报告云文档，不覆盖原始审查报告。
2. 标题使用 `Java 代码修复报告 - {PROJECT_NAME} - {YYYY-MM-DD}`。
3. 上传内容必须来自本地 Markdown 修复报告文件。

示例：

```bash
cd "$PROJECT_DIR" && lark-cli docs +create \
  --title "Java 代码修复报告 - demo - 2026-05-07" \
  --markdown @code-fix-report-demo-20260507-153000.md
```

---

## 六、回退规则

出现以下任一情况时，必须回退为本地 Markdown 报告：

- `lark-cli` 不存在
- 登录态或权限不足
- 文档读取失败
- Base 读取失败
- Base 缺少关键字段
- 记录更新失败且无法安全重试

回退后仍应完成代码修复和验证，但最终报告必须包含：

- 原计划飞书目标
- 失败命令
- 错误摘要
- 已生成的本地报告路径
- 建议用户补充权限或手动同步的字段列表
