# P0 严重级别收紧设计

## 背景与目标

当前 P0 定义使用“会直接导致生产事故、严重安全漏洞或关键数据错误”等原则性描述，并列举 SQL 注入、事务失效、权限绕过、关键外部调用无超时等示例。部分示例缺少生产可达性、证据完整性和事故级后果门槛，容易让静态代码形态直接升级为 P0。

本次调整只收紧 P0 分级，不建立扫描与修复之间的跨轮闭环，也不要求不同模型产生相同发现。目标是让不同模型可以发现不同问题，但只有证据充分、现实可触发且足以阻断上线的问题进入 P0。

## 分级决策

### P0 硬门槛

问题必须同时满足以下条件才能进入 P0：

1. **生产可达**：问题位于真实生产路径，存在明确的入口、调用链或生效配置，不能只依据孤立代码形态推测。
2. **证据完整**：代码、配置或调用链证据足以直接证明问题成立；置信度必须为高。
3. **事故级影响**：可导致严重安全突破、关键数据错误或丢失、资金错误、系统性不可用等生产事故。
4. **缺少有效防护**：没有已生效的鉴权、参数化、超时、隔离、限流、回滚、补偿或其他足以阻断事故的机制。
5. **阻断发布**：如果问题随当前代码上线，应立即阻断发布并修复。

任一条件不满足，都不得标为 P0。中、低置信度问题不得进入 P0。

### 未通过 P0 门槛时的归类

- 问题已经由完整证据证实，但影响未达到事故级或仍有有效缓解机制：下移到 P1。
- 风险可能达到事故级，但生产可达性、调用链、运行配置或防护状态尚未证实：归入待确认。
- 影响仅涉及局部可维护性、规范或优化：继续按现有规则归入 P2/P3。
- 在支持 P1/P2/P3/待确认输出的模式中，不得因为候选问题未通过 P0 门槛而静默丢弃。

## 典型边界

- SQL/NoSQL 注入：必须证明不可信输入到达未参数化的危险查询，并且现有校验或框架绑定不能阻断，才能定为 P0；仅看到字符串拼接但来源不明时进入待确认。
- 权限绕过：必须证明未授权主体可访问受保护资源或执行敏感操作，才能定为 P0；仅缺少某个注解但存在其他鉴权链时不能定为 P0。
- 事务问题：必须证明关键写操作会发生部分提交、不可恢复的数据不一致或资金错误，才能定为 P0；一般事务边界不合理下移 P1。
- 外部调用无超时：必须证明调用位于关键同步路径、没有其他时间边界，并可能耗尽共享资源导致系统性不可用，才能定为 P0；一般缺少显式超时下移 P1。
- 硬编码凭据：必须证明是有效生产凭据且会造成现实安全突破，才能定为 P0；测试值、示例值或有效性未知的值不得直接定为 P0。

## 模式行为

### fast

fast 保持纯 P0 模式：

- 只输出满足全部 P0 硬门槛的问题。
- 不输出 P1、P2、P3 或待确认项。
- 未通过 P0 门槛的候选问题不会出现在 fast 报告中；这是模式边界，不代表这些问题不存在。

AskUserQuestion 的 fast 选项必须直观展示“仅输出 P0”，不能只写“快速扫雷”。选项描述必须说明只报告已证实、足以阻断上线的 P0，P1/P2/P3 和待确认项均不输出。

最终执行计划在选择 fast 时额外展示：

```text
- 输出级别：仅 P0
```

### standard / deep / security

这些模式继续输出其模式矩阵允许的完整严重级别。原 P0 候选未通过硬门槛时，按证据和影响进入 P1、待确认或更低级别，不得直接删除。

## 修改范围

- `agents/cc-code-reviewer.md`：收紧 P0 定义、增加硬门槛、下移规则和典型边界。
- `references/review-framework.md`：同步 P0 判定原则和 fast 纯 P0 语义。
- `references/report-format.md`：要求 P0 条目体现生产可达性、事故级影响和防护状态证据。
- `skills/cc-code-reviewer/SKILL.md`：修改 fast AskUserQuestion 文案，并在执行计划中展示“输出级别：仅 P0”。
- `references/examples.md`：同步 fast 选项及执行计划示例；避免无完整证据链的 P0 示例。
- `tests/test_contract_docs.sh`：增加 P0 硬门槛、降级完整性、fast 交互提示和执行计划提示的契约断言。

不修改扫描批次、跨轮基线、问题指纹、fixer 范围或报告存储结构。

## 验证标准

1. 契约测试能在缺少任一关键规则时失败。
2. fast AskUserQuestion 选项和说明明确包含“仅输出 P0”。
3. fast 执行计划明确包含“输出级别：仅 P0”。
4. P0 规则明确要求高置信度、生产可达、完整证据、事故级影响、无有效防护和阻断发布。
5. 非 fast 模式下，未通过 P0 门槛的候选问题明确下移到 P1、待确认或更低级别，不会静默丢弃。
6. `bash tests/run_all.sh` 通过，且 `git diff --check` 无错误。
