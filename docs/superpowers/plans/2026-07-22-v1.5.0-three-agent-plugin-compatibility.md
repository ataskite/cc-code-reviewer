# v1.5.0 Claude Code / Codex / ZCode 插件兼容 Implementation Plan

> 本计划用于在不复制审查内核的前提下，让 cc-code-reviewer 1.5.0 同时支持 Claude Code、OpenAI Codex 和智谱 ZCode 的插件安装、Skill 调用与 Agent 调度。

**Goal:** v1.5.0 在同一个 Git 仓库、同一个版本号下，可被 Claude Code、Codex CLI/Desktop 和 ZCode 安装；三个入口均可运行 scan、ignore、fix，并保持现有人工确认、审查边界、批次合并和报告契约。

**Architecture:** 三端原生清单共同发现根 `skills/` 唯一权威流程；平台差异限制在插件清单、runtime adapter、交互映射、模型映射和子 Agent 调度。共享层只认识平台无关的 `RUNTIME_ID`、`PLUGIN_ROOT`、`MODEL_PROFILE`、`INTERACT` 和 `DISPATCH_AGENT`，不得直接依赖 Claude/Codex/ZCode 的工具名。

**Release target:** `1.5.0`

**Development branch:** `codex/v1.5.0-three-agent-plugins`

**Design spec:** `docs/superpowers/specs/2026-07-22-v1.5.0-three-agent-plugin-compatibility-design.md`

**Upstream baseline:** 从 `feat/python-reviewer` 的 `2113200` 创建。创建分支时工作区已有未提交的 Python/前端/v1.5.0 修改；实施时必须窄范围暂存，不得把这些既有修改误判为本计划新增内容。

## 1. 支持范围与非目标

### 1.1 v1.5.0 必须支持

| 能力 | Claude Code | Codex | ZCode |
|---|---|---|---|
| 从 Git/Marketplace 安装 | 必须 | 必须 | 必须 |
| 发现三个 Skill：scan / ignore / fix | 必须 | 必须 | 必须 |
| 单 Agent 审查 | 必须 | 必须 | 必须 |
| 批量/并行审查与合并 | 必须 | 必须 | 必须 |
| 人工逐步确认 | 保持现状 | 语义等价 | 语义等价 |
| 项目级 ignore | 必须 | 必须 | 必须 |
| 报告驱动 fix | 必须 | 必须 | 必须 |
| 本地 Markdown 报告 | 必须 | 必须 | 必须 |
| 飞书输出 | 能力存在时 | 能力存在时 | 能力存在时 |

### 1.2 明确非目标

- 不为三个平台复制三套脚本、规则和报告格式。
- 不在 v1.5.0 重新设计审查维度、严重级别、语言适配器或分批算法。
- 不承诺 Codex IDE Extension 的插件安装；Codex 官方当前插件入口以 CLI/Desktop 为准，IDE 场景仅提供项目级 Skill 降级说明。
- 不把 ZCode 对 `.claude-plugin` / `.codex-plugin` 的当前兼容行为当作长期 API；必须提供原生 `.zcode-plugin/plugin.json`。
- 不以进入 OpenAI 公共插件目录或 ZCode 官方目录作为 1.5.0 发版阻塞项；Git Marketplace 安装通过即可。
- 不新增 Windows 支持。

## 2. 目标目录结构

```text
.claude-plugin/
  plugin.json                         # 保留现有 Claude Code 清单
  marketplace.json

.codex-plugin/
  plugin.json                         # Codex 原生清单

.agents/plugins/
  marketplace.json                    # Codex Git Marketplace 清单

.zcode-plugin/
  plugin.json                         # ZCode 原生清单

skills/                               # 三端共同发现的唯一权威流程
  cc-code-reviewer/SKILL.md
  cc-code-ignore/SKILL.md
  cc-code-fixer/SKILL.md

runtime/
  contract.md                         # 平台无关运行时契约
  claude-code.md                      # AskUserQuestion / Claude Agent 映射
  codex.md                            # Codex 交互 / subagent 映射
  zcode.md                            # ZCode 交互 / subagent 映射

agents/                               # 共享审查 Prompt，不再绑定 sonnet
scripts/                              # 共享确定性内核
references/                           # 共享规则和报告格式
tests/runtime/                        # 清单、能力映射和安装契约测试
```

说明：Codex 官方 validator 要求 `plugin.json.skills` 指向根 `skills/`，因此三端原生清单共同发现同一组权威 Skill。Skill 根据当前宿主身份选择 adapter；身份不明确时在预扫描前失败，不通过工具或 cwd 猜测。

## 3. 跨平台运行时契约

### 3.1 插件根目录

新增统一逻辑变量 `PLUGIN_ROOT`：

- Claude Code 适配器从 `${CLAUDE_PLUGIN_ROOT}` 注入。
- 三端从根 Skill 资源位置按固定相对层级 `../..` 推导并注入；禁止使用 shell `$0` 或当前工作目录。
- 共享 Skill、Agent Prompt 和脚本只使用 `${PLUGIN_ROOT}`。
- 路径必须支持空格、符号链接和 Git Marketplace 缓存目录。
- 不允许依赖当前工作目录猜测插件根目录。

### 3.2 人工确认

共享契约保留“不跳步、不合并关键确认、确认后才执行”的业务不变量，但不再绑定 `AskUserQuestion` 这个工具名：

| 逻辑能力 | Claude Code | Codex | ZCode |
|---|---|---|---|
| 单选确认 | `AskUserQuestion` | 平台结构化输入；不可用时逐轮单问 | 平台结构化输入 |
| 多选报告目标 | `multiSelect` | 拆成组合选项或连续单选 | 平台原生多选；不可用时连续单选 |
| 4 个以上选项 | 原样展示 | 分级菜单，满足 Codex 选项上限 | 原样或分级菜单 |
| 最终执行确认 | 单独一步 | 单独一步 | 单独一步 |

适配器可以改变交互呈现，但不得改变已确认范围、默认值或跳过最终确认。

### 3.3 模型选择

共享层使用平台无关模型档位：

- `inherit`：默认，继承当前会话模型。
- `economy`：低成本模型档位。
- `balanced`：标准模型档位。
- `maximum`：最高质量/推理强度档位。

Claude Code 适配器可以映射到当前可用的 Claude 模型；Codex 适配器映射到当前模型及 reasoning effort；ZCode 适配器映射到它暴露的模型。共享 Skill 中不得出现强制 `sonnet`、`opus`、`haiku` 或特定 Codex 模型 ID。

### 3.4 子 Agent 调度

- 共享 `agents/*.md` 只保留角色、输入、边界和输出契约。
- 删除或平台化 `model: sonnet` 等 Claude 专属 frontmatter。
- Claude Code：继续使用插件 Agent 类型。
- Codex：由主 Skill 读取共享 Agent Prompt，注入参数后派发通用 subagent；不要求写入用户的 `~/.codex/agents`。
- ZCode：优先通过插件原生 subagent 注册；若注册能力不足，按 Codex 的 Prompt 注入方式降级。
- 三个平台的 batch agent 都必须写当前批次 status/result 文件，主 Skill 统一调用现有 merge/status 脚本。

### 手工 smoke matrix

每个平台在全新安装后至少执行：

1. 安装并开启新会话，确认三个 Skill 可见。
2. 对小型 fixture 执行 Java 单 Agent scan，并生成本地 Markdown。
3. 执行一次前端或 Python file-token batch scan，确认批次状态和合并报告。
4. 从报告选择一个问题运行 fix，确认最终执行前存在独立确认。
5. 从报告创建一条 ignore 规则，再次 scan 验证被过滤。
6. 无 lark-cli 环境验证本地降级；有条件时补一次飞书输出验证。

### 安装路径

- Claude Code：现有 `claude plugin marketplace add` + `claude plugin install`。
- Codex：`codex plugin marketplace add <owner/repo>` + `codex plugin add <plugin>@<marketplace>`，安装后开启新会话。
- ZCode：Settings → Plugins → Marketplace，添加 GitHub/Git source 后安装。

**Gate:** 三个平台的 smoke matrix 均记录版本、安装来源、结果和已知限制；任何核心流程失败都阻塞 1.5.0。

## 6. 完成定义

只有同时满足以下条件，才可以宣布 v1.5.0 支持三个 Agent 产品：

- 同一 Git 仓库能被 Claude Code、Codex、ZCode 安装。
- 三个平台都发现 scan、ignore、fix 三个 Skill。
- 三个平台都通过单 Agent scan、batch scan、ignore、fix 的 smoke test。
- 人工确认、正式扫描边界、报告合并、Feishu 职责边界没有弱化。
- 三个平台清单和文档版本均为 `1.5.0`，自动化测试可以阻止漂移。
- 共享内核没有出现三份复制实现，平台差异被限制在 runtime adapter 和 manifest。
